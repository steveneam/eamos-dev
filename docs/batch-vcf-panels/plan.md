## How to read this runbook

- Each phase row = a **discrete, independently-verifiable unit**. Order is such that **each step builds on a green predecessor** — do not start a step until the prior step's gate is green.
- **Files** column: `EDIT path (anchor)` or `CREATE path`. Anchors are current `file:line` ground-truthed 2026-06-06.
- **⚠ GATED** = durable structural / visual / nav / revenue-facing change — **needs Steven's explicit OK before ship** (recommendation ≠ authorization; see §7 of spec). A gated step may be *built and locally verified* but must NOT be merged/shipped to `main` until approved.
- **Mock-first:** everything in the BUILDABLE-NOW lane works offline against `panels.mock.ts` + the `createBatch`/`getBatchJob` mock fallbacks. The CODEX-BLOCKED lane is a separate table — those features ship as FE shell now and light up when Codex ships the named backend piece.

## Risks

1. **Approval gating blocks the visible spine.** P3 (server arm), P6 (tier gate), P4 (branding), P8/P10 (tabs) are all ⚠ GATED. If Steven doesn't approve §7.1/§7.2/§7.3/§7.4, only P1/P2/P5/P7/P9 ship — a real but partial slice. *Mitigation:* build+verify gated phases locally, present for approval as a batch; non-gated phases (P1/P2/P5/P7/P9) carry independent value.
2. **`CLIENT_MAX` / threshold numbers are placeholders (D-3, Codex's call).** Intake-card copy ("Showing first 2,000…", ≤5 MB boundary) is wrong if the real threshold differs. *Mitigation:* one named constant; copy reads it. Confirm D-3 before shipping P2/P3 copy.
3. **Cap numbers `CAP_P`/`CAP_M` unset (D-2).** P6 enforcement is parametric until Steven sets them; shipping live enforcement on guessed caps is revenue-facing risk. *Mitigation:* gate (§7.2) holds live enforcement; dev-default never blocks local dev.
4. **Virtualization without a library (P9).** No virtualization dep in `package.json`; DESIGN.md forbids new deps without cause. Hand-rolled windowing must keep sticky `<thead>` + scroll-restore correct. *Mitigation:* fixed row height → simple offset windowing; verify smooth scroll + DOM node count at 1500 rows.
5. **Stub backend masks real failures (P8).** `runBatch` currently swallows everything into the mock fallback (`CompareClient.tsx:121-123`); splitting real `failed` out risks surfacing the stub's own non-failures as errors. *Mitigation:* only treat `status==='failed'/'cancelled'` + genuine network throw as error; keep offline-mock fallback intact (invariant #4).
6. **Provenance honesty regression (P4).** Hard-coding "PanelApp Australia" would mislabel the live backend's `custom` panels (legal exposure, D-1). *Mitigation:* render live `source` only; §7.3 gate forbids hard-coded branding.
7. **No automated test net.** `app/web` has no Vitest — all verification is tsc + lint + manual browser. Logic regressions in `variant-file.ts`/`compare-filters.ts`/`cohort-export.ts` are caught only by the browser step. *Mitigation:* keep pure functions small and exercised by the named browser conditions; consider a Claude-owned lightweight test harness only if Steven asks (out of scope here).
8. **Dev-server collision.** Codex may own the `:3000` dev server. *Mitigation:* `browser-verify` against the existing instance or a Claude-owned port; kill any server you start before `/clear` (memory `feedback_background_process_cleanup`).
